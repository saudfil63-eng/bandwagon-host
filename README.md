# 搬瓦工重装系统指南：KiwiVM 与 DD 的选择和操作

更换 Linux 发行版、清理已经无法正常使用的系统，或尝试自定义镜像时，都可能需要重新安装服务器。搬瓦工的 KiwiVM 控制面板提供了选取系统模板的入口；有自定义需求的用户也可以考虑通过 DD 写入镜像。两者的操作方式和准备工作不同，不必为了普通的系统重装而直接使用 DD。

本文从选择方法、准备数据到安装后的检查，整理一条完整的操作思路。重装会清除原系统的数据，开始之前请先确认哪些内容需要保留，以及备份能否用于恢复。

## 先选择重装方式

| 比较项目 | KiwiVM 系统重装 | DD 写入镜像 |
| --- | --- | --- |
| 操作入口 | 控制面板的 Install new OS | 先连接 Linux，再通过 SSH 操作 |
| 系统选择 | 面板提供的 Linux 系统模板 | 自行选择适合的系统镜像 |
| 操作门槛 | 按面板步骤选择并确认 | 需要理解镜像写入、引导和后续连接 |
| 镜像来源 | 面板提供的模板 | 由操作者选择并核实来源 |
| 数据影响 | 清除 VPS 原有数据 | 写入磁盘会覆盖原有系统和数据 |

如果只是想安装 Ubuntu、Debian 等 Linux，或希望重新获得一个干净的系统环境，先查看面板里的模板通常更直接。选项以面板实际显示为准；选择前还应考虑现有应用依赖的发行版和版本，避免装好后才发现软件环境不匹配。

DD 是将系统镜像写入磁盘的进阶方式，适合面板模板不能满足需求、并且能够自行判断镜像来源和兼容性的用户。它不是对普通重装的简单补充：原系统被替换后，连接方式、登录凭据和恢复步骤都可能发生变化。KVM 架构为这类操作提供了条件，但不代表任意镜像都能正常启动或兼容现有环境；旧 OpenVZ 环境不适用这里介绍的 DD 路径。

KVM 说的是虚拟化架构，Basic、CN2 GIA-E 等则是套餐或线路的区分。选择哪种重装方法时，首先看架构和实际需求，不要把线路名称当成操作系统安装方式。

## 重装前准备：先想清楚如何恢复

**整理并备份需要的数据。** 网站文件、数据库、应用配置和其他需要保留的内容都应在操作前另行保存。仅有一份文件不等于已经完成备份：检查备份是否包含所需内容，并确认自己知道如何读取和恢复。数据库尤其需要考虑应用与数据之间的对应关系，避免恢复了程序却遗漏数据。

KiwiVM 提供 Snapshots（快照）和 Automatic Backups（自动备份）功能，可以在准备恢复方案时了解它们的可用情况。具体条件应以所用服务和面板显示为准；不要把未经验证的快照当作唯一恢复手段，也不要假设任何情况下都能直接回滚。对重要数据，独立保存并验证可用的备份更有助于重装后的检查。

**记录现有环境和访问方式。** 在清除系统前，记下服务器地址、需要使用的账号、当前服务配置及恢复业务所需的信息，并确认自己能够登录账户和 KiwiVM。原有密码、端口和系统配置不应被当作重装后的必然配置：安装结束后，应重新查看面板给出的连接信息。

**确认目标系统。** 面板重装时，先了解应用需要的发行版及版本，再从实际列表选择。使用自定义镜像时，还要核实来源、适用架构、引导方式和初始凭据。如果无法判断镜像是否可信，先不要将它写入服务器。

重装系统与更换 IP、迁移机房或改变线路是不同操作。它解决的是磁盘上的系统环境问题，不能把它当作调整网络线路的替代方案。

## 在 KiwiVM 中重装 Linux

以下流程适合选择面板提供的系统模板。操作前应安排好服务中断和数据恢复，确认准备完成后再进入控制面板。

### 1. 找到服务器并进入面板

登录搬瓦工账户，在 **Services → My Services** 中找到需要操作的 VPS，进入对应的 **KiwiVM Control Panel**。如果账户下有多台服务器，先核对所选服务，避免在错误的实例上执行清除操作。确认能够访问面板后，再继续检查服务器状态。

### 2. 停止正在运行的 VPS

在 **Main Controls** 查看当前状态。如果服务器正在运行，点击 **Stop** 并等待其完全关机。运行中的 VPS 不能直接按此流程重装；如果面板提示 `Unable to reload a running VPS`，应先检查是否已经停止，而不是反复提交安装。

关机前宜先完成备份，特别是需要通过原系统访问的数据。停止后再发现遗漏，可能需要重新启动原环境才能处理，因此应把数据核对放在这一步之前。

### 3. 选择系统模板

打开左侧的 **Install new OS**，查看可用系统和版本。需要安装 Debian 或 Ubuntu 时，从列表中选择与应用需求相符的模板；参考资料也提到了 CentOS、Rocky Linux 等选项，但具体是否可选仍取决于面板当时显示的列表。

部分模板名称带有 `_bbr` 后缀。参考资料将其描述为启用 BBR 的版本；BBR 是一种 TCP 拥塞控制算法。选择时可以根据自己的系统和网络配置需求决定是否使用该模板，不必把这个后缀理解为速度或丢包表现的保证。无论选择哪一项，都要确认版本与之后准备安装的软件相符。

### 4. 确认清除并开始安装

检查目标服务器和所选模板，阅读面板中的数据清除提示。确认备份和恢复准备已经完成后，勾选同意数据丢失的选项，再点击 **Reload**。这个确认并不是普通的软件更新：原系统中的文件和配置会被清除，后续需要从备份恢复所需内容。

### 5. 保存新连接信息

安装完成后，记录并妥善保存面板显示的新 **root 密码**和 **SSH 端口**，不要继续假定旧密码或默认端口仍然适用。使用服务器地址、新端口和新凭据连接，确认能够进入预期的系统。

首次登录后，先核对系统版本和基本配置，再按事先准备的顺序恢复数据与应用。连接成功只说明可以访问系统，并不等于网站、数据库或其他业务已经恢复；应分别检查它们的配置和运行状态。

## DD 与自定义镜像：什么时候考虑

当所需系统不在面板列表中，或者需要高度定制的环境时，可以评估 DD。参考资料描述的基本顺序是：先用 KiwiVM 安装一个可通过 SSH 访问的 Linux，以 root 登录，再使用可信的镜像写入方案将目标镜像写入磁盘。写入会替换原系统，因此原来的 SSH 会话可能中断；安装期间可借助 KiwiVM 的 **VNC** 查看状态，完成后使用新系统的连接凭据访问。

这里没有提供通用脚本或命令，因为执行方式取决于所选镜像和方案。操作前应自行核实镜像的来源及适用环境，了解写入和引导步骤，并确认出现问题时能否通过控制面板继续处理。镜像若带有默认密码，安装后应及时修改；来源不明的镜像即使能够启动，也不宜直接用于承载重要数据。

Windows 需求可以考虑 DD，也可以查看 KiwiVM 的 **Mount ISO** 功能，通过挂载可引导镜像进行安装。两者的安装过程不同：DD 是写入现成镜像，ISO 路径则需要处理安装过程中的选择和配置。镜像能否使用、面板提供哪些挂载选项，应以实际环境为准；有明确需求并能处理安装和登录问题时，再选择适合自己的路径。

## 重装后检查：连接、数据与服务

### SSH 连接失败怎么办？

首先回到 KiwiVM 查看 **SSH port**，确认连接时使用的是新端口，而不是沿用重装前的设置。再核对服务器地址、用户名和新密码；面板重装后可使用显示的 root 凭据进行初次连接。检查这些信息时，不要把密码公开到工单、聊天或公开文档中。

如果端口和凭据无误仍无法连接，还应检查防火墙等连接条件，并结合面板显示的服务器状态排查。SSH 失败可能有不同原因，端口只是值得优先核对的一项。使用自定义镜像时，也要参照该镜像的登录方式，不能假定它与面板模板完全相同。

### 怎样确认恢复完成？

先检查目标系统是否启动、版本是否符合预期，再恢复应用所需的文件、数据库和配置。恢复后分别验证服务是否运行，以及数据能否被应用正确读取；确认正常之前，不要仅凭 SSH 可以登录就恢复业务。对照重装前记录的环境逐项检查，有助于发现遗漏的配置或数据。

重装本身用于替换系统，不等同于更换 IP，也不能直接解决线路选择造成的网络问题。如果原先的问题发生在网络访问环节，应区分系统配置和线路因素，再决定是否需要进一步排查；不必把反复重装作为唯一手段。
